# Crypto {Kurt} Ai v1.0

Облачный Bybit USDT perpetual сканер: RSI(14) + рост Open Interest за ~45 мин + объём 15m относительно предыдущих 20 свечей.

## Стратегия
- 150 наиболее ликвидных USDT линейных фьючерсов с оборотом >= 10 млн USDT/сутки; 6 партий по ~25.
- LONG: RSI <= 35 и растёт, свеча бычья, OI +1% или больше, объём >= 1.4x.
- SHORT: RSI >= 65 и снижается, свеча медвежья, OI +1% или больше, объём >= 1.4x.
- Спред <= 0.2%; вход — закрытие подтверждённой 15m свечи.
- SL = 1.5 ATR(14); TP1 = 1R, TP2 = 1.8R. Оценка 0–100 — индекс условий, НЕ вероятность прибыли.
- Это новая реализация базовой идеи, не дословное восстановление неизвестных правил самого первого архива.

## Установка
1. Создать новый репозиторий GitHub из содержимого папки, импортировать в Vercel как Next.js.
2. В Vercel -> Settings -> Environment Variables добавить пять переменных из `.env.example`.
3. В cron-job.org создать GET задачи с HTTP заголовком `Authorization: Bearer <CRON_SECRET>`:
   - `/api/scan?batch=0` каждую 15-ю минуту, например 00,15,30,45;
   - batch=1 на 02,17,32,47; batch=2 на 04,19,34,49; batch=3 на 06,21,36,51; batch=4 на 08,23,38,53; batch=5 на 10,25,40,55.
   - `/api/settle` каждые 5 минут.
   - `/api/report` каждый час, например в 59-ю минуту.
4. Для нового чистого учёта создать **отдельную** Upstash Redis базу и вписать её URL и token. Существующую базу других проектов удалять не требуется.
5. Время отчёта отображается в часовом поясе Europe/Kyiv.

## Важные ограничения
- Bybit API может возвращать HTTP 403 из некоторых регионов Vercel. В этом случае необходимо разрешённое подключение к API из доступного региона; никакой код не гарантирует обход ограничения.
- Данные OI и свечей должны быть доступны на Bybit. Статистика обновляется по закрытым минутным свечам; одновременные TP/SL в одной свече помечаются как AMBIGUOUS.
- Из-за ограничения 200 минутных свечей за запрос мониторинг следует вызывать регулярно; после длительного простоя возможен пропуск истории. Не используйте статистику как торговую гарантию.
- Фактическое исполнение по цене сигнала не гарантировано; комиссии и проскальзывание не учитываются.
- Сигналы не являются финансовой рекомендацией.

## Изменения v1.1 (технические, стратегия не менялась)
- Сканирование до пяти монет параллельно вместо строго последовательных запросов. Ограничение времени Vercel всё ещё зависит от задержек внешних API.
- Не формируем новый сигнал, если последняя закрытая 15-минутная свеча устарела более чем на 16 минут после закрытия.
- Проверка TP/SL обрабатывает до 180 минут истории за вызов, без пропуска более старых интервалов после простоя; оставшаяся история догоняется последующими вызовами `/api/settle`.
- При пробеле в минутных свечах монитор не перескакивает через него, а повторяет проверку позднее.
- Почасовой отчёт объединяет только партии одного 15-минутного цикла, а не данные нескольких циклов за 65 минут. Если часть партий не запускалась, отчёт покажет неполный цикл.
- Вход по закрытию свечи остаётся модельным: реальное исполнение после Telegram-уведомления не подтверждается биржей. Отчёт показывает **модельные**, а не фактически исполненные сделки.
- Для надёжного догоняющего мониторинга после длительного простоя требуется регулярный cron. При большом числе открытых сделок вызов `/api/settle` всё ещё может упереться в лимит времени хостинга.
