# ZONE SIGNAL — новый Bybit → Telegram сканер

Отдельный проект с нуля. Не торгует автоматически. Сканирует 150 ликвидных USDT perpetual инструментов Bybit, шесть групп по 25, анализирует **закрытые часовые свечи** на повторные зоны локальных экстремумов и реакцию цены. Для каждой найденной ситуации отправляет Telegram-сообщение с зоной входа, тремя структурными целями и стопом. Отдельный endpoint проверяет уже отправленные сигналы по **закрытым минутным свечам** и отправляет уведомления при достижении TP1, TP2, TP3, SL.

**Важно:** исходный закрытый алгоритм стороннего трейдера неизвестен. Это воспроизводимая формализация наблюдаемого Price Action, а не его точная копия. В отличие от картинок, реальные уровни рассчитываются автоматически. До использования в торговле нужен исторический и демо-тест.

## Установка

1. Создать **новый** GitHub репозиторий и загрузить содержимое этой папки (не вложенную папку).
2. Импортировать репозиторий в Vercel как Next.js.
3. В Vercel → Settings → Environment Variables добавить значения из `.env.example`:
   - `TELEGRAM_BOT_TOKEN` — токен бота от BotFather.
   - `TELEGRAM_CHAT_ID` — ID личного чата или канала, в котором бот имеет право писать.
   - `CRON_SECRET` — произвольный длинный секрет; передавать в заголовке `Authorization: Bearer <CRON_SECRET>`.
   - `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — REST credentials Upstash Redis.
   - `TOP_COINS=150` — сколько ликвидных монет брать.
4. Deploy. Убедиться, что Bybit API доступен из региона сервера Vercel. Если Bybit возвращает HTTP 403, это ограничение доступа к API, а не отсутствие сигналов.
5. В cron-job.org настроить HTTP GET запросы с заголовком `Authorization: Bearer <CRON_SECRET>`:
   - `/api/scan?batch=0` … `/api/scan?batch=5` — **каждые 60 минут**, распределить запуски по минутам 03, 05, 07, 09, 11, 13 после закрытия часовой свечи.
   - `/api/settle?batch=0` … `/api/settle?batch=5` — **каждые 10 минут**, распределить запуски по минутам 00, 01, 02, 03, 04, 05.
   - `/api/report` — раз в день.

**Предупреждение по бесплатному Vercel:** функции и лимиты исполнения зависят от тарифа; каждый endpoint рассчитан на ограниченное число инструментов. Если в ответе `errors`, их нужно устранять. При большом количестве накопленных сигналов расчёт исходов может занять несколько циклов.

## Что приходит в Telegram

- `📢 SYMBOL LONG/SHORT` — новая идея, зона входа, TP1/TP2/TP3, SL и объяснение.
- `📊 SYMBOL` — когда закрытая 1m свеча впервые коснулась нового TP или SL.
- `📈 ZONE SIGNAL — отчёт` — количество открытых, частичных, полностью достигнутых и остановленных сделок.

**Семантика исходов:** `TP3` — все три цели достигнуты без ранее отмеченного стопа; `PARTIAL` — достигнут один или два тейка; `PARTIAL_SL` — после частичных тейков сработал стоп; `SL` — стоп без тейков. Если TP и SL в пределах одной 1m свечи, порядок неизвестен: консервативно считается SL, и сообщение помечается как неоднозначное. Сигнал фиксирует цену на закрытии часовой свечи, а не реальное исполнение ордера. Статистика **не равна PnL**, так как нет размера позиции, комиссий, проскальзывания и частичного закрытия.

## Тестирование

```bash
npm install
npm test
npm run build
```

Проверить ответы endpoint вручную с Authorization; ошибки не скрываются. API не использует ключи Bybit, потому что нужны только публичные рыночные данные.

## Ограничения первой версии

- Не генерирует картинку со стрелкой, как у трейдера; отправляет текст с рассчитанными уровнями.
- Пока нет исторического бэктеста, поэтому прибыльность и частота сигналов не установлены.
- Из-за ограничений истории 1m свечей, если бот долго не запускался, точный исход старой сделки может быть недоступен. Для надёжного учёта нужен регулярный settle.
- При сетевом сбое между сохранением сигнала и отправкой Telegram повторная рассылка не производится, чтобы не дублировать сигнал. Ошибка появится в JSON-ответе cron.
